The Rubik's Cube: Structure & Math

6 faces, 54 stickers, ~43 quintillion possible states. Let's break it down.

Face & Sticker Layout

Each face has 9 stickers in a 3×3 grid. Our solver uses standard notation: Up, Right, Front, Down, Left, Back.

Colors map to faces: White→U, Blue→R, Red→F, Yellow→D, Green→L, Orange→B.

State Representation

The cube state is encoded as a 54-character string (9 per face) for the Kociemba algorithm — one of the fastest optimal solvers.

K-Means: Finding the Dominant Color

A sticker image has many pixels (lighting, shadows). K-means with k=1 finds the "center" — the dominant color. Drag to rotate the 3D RGB space.

The Algorithm

  1. Flatten pixels into (R,G,B) points in 3D space.
  2. Filter out very dark pixels (shadows).
  3. K-means with 1 cluster: minimize sum of squared distances to centroid.
  4. The cluster center = dominant color.

KMeans(n_clusters=1).fit(pixels) → one robust "average" color per sticker.

K-Nearest Neighbors: Classifying Colors

Given a sticker's color (BGR, HSV, LAB features), which of the 6 cube colors is it? KNN: ask the k closest training examples. Drag the center sphere in 3D RGB space — lines show k=3 nearest neighbors.

The Idea

We train on labeled samples (R, G, B, Y, O, W). For a new sticker:

  1. Extract 9 features: B, G, R, H, S, V, L, A, B (BGR + HSV + LAB).
  2. Scale features (StandardScaler) so units don't dominate.
  3. Find k=3 nearest training points (Euclidean distance).
  4. Majority vote → predicted color.

Computer Vision: Detecting Faces

From raw image to 6 face crops: edge detection, contours, and region extraction.

Pipeline

  1. Grayscale → single channel for geometry.
  2. Gaussian blur → reduce noise before edges.
  3. Canny edge detection → find sharp intensity changes.
  4. Contours → closed boundaries; approximate to polygons.
  5. Square filter → 4-vertex contours with area > threshold.
  6. Region extraction → divide into 3×3 grid for stickers.

Kociemba as U-Net

Encoder (Phase 1) reduces to G₁ · Decoder (Phase 2) solves. Processing blocks between states; skip connections carry info forward.

The Robot: Hardware That Solves

Our physical solver — 6-axis stepper rig driven by an ESP32. The solution flows from Python to firmware; one trigger executes the full algorithm.

Hardware Stack

  • MCU: ESP32
  • Motors: 6× NEMA 17 stepper motors
  • Drivers: 6× A4988 (one per face)
  • Interface: Serial @ 115200 baud

Each motor uses 3 pins: STEP, DIR, ENABLE. Step counts and speed profiles (ramp, delays) are calibrated per motor.

Firmware Sketches

  • robot.ino — Test sketch: paste any algorithm (e.g. R2B'LD) in Serial Monitor, press Enter to run.
  • run_solution.ino — Production: the Python solver writes the solution here; flash to ESP32, then press SPACE + ENTER to execute.
